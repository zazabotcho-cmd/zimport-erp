ZIMPORT — "STUCK AFTER LOADING" FIX

WHAT WAS WRONG
The page loads a cloud library from the internet (cdn.jsdelivr.net) before it can
sign you in. If that library was slow, blocked, or failed to load for any reason
(network hiccup, firewall, ad-blocker, temporary outage), the program hit a silent
error and never finished setting up the Sign In button, Forgot Password button,
Sign Out button, and Sync Now button. Nothing on the page was actually broken —
those buttons simply never got "switched on," so clicking them did nothing and the
screen looked permanently stuck, with no error message shown to you.

WHAT WAS CHANGED
Only one file was changed: online-adapter.js.
- The Sign In, Forgot Password, Sign Out, and Sync Now buttons are now switched on
  immediately, no matter what happens with the cloud library.
- If the cloud library fails to load, or the connection can't start, the login
  screen now shows a clear message explaining what happened and a "Retry
  connection" button, instead of silently doing nothing.
- Clicking Sign In while the cloud connection isn't ready now shows a message
  telling you to check your internet connection and retry, instead of appearing
  to do nothing.

This was tested in an automated browser: with the cloud library blocked, the app
now shows the explanatory message and a working Retry button; with the cloud
library available, sign-in works exactly as before.

WHAT YOU NEED TO DO
1. Re-upload every file in this ZIP to your web host (Cloudflare Pages, Netlify,
   etc.), replacing the old files. The important one is online-adapter.js.
2. Your Supabase project URL/keys in online-config.js were left exactly as they
   were — no need to reconfigure anything.
3. If the app ever shows "Cloud library failed to load" again, it means your
   internet connection (or something blocking cdn.jsdelivr.net) is the cause —
   click "Retry connection" or reload the page once your connection is back.

NOTE (not related to the stuck issue, no action needed)
While testing, the browser flagged a handful of duplicate HTML element IDs in two
of the Financial sections (e.g. ssFinAdDescription1-6, ssFinInvoiceNumber). This is
a pre-existing, unrelated cosmetic issue in two similar financial sub-pages and did
not cause the freeze — it wasn't touched in this fix so nothing already working was
put at risk. Mention it if you'd like it looked at separately.
