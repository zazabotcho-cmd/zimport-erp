ZIMPORT — "STUCK AFTER LOADING" FIX (v2)

WHAT WAS WRONG (two related bugs, both in online-adapter.js)

1) If the cloud library (loaded from the internet) was slow, blocked, or failed to
   load, the program hit a silent error and never finished setting up the Sign In,
   Forgot Password, Sign Out, and Sync Now buttons. Clicking them did nothing.

2) Even when the cloud library loaded fine, if the Sign In button's actual network
   request to your Supabase project failed for any reason (a connection hiccup, a
   firewall, DNS issues, or the project itself being unreachable/paused), that
   failure was never caught. The click would silently do nothing — no error
   message, no spinner, nothing — which looks exactly like the screen being
   "stuck." I reproduced this exact scenario in an automated test and confirmed it
   was the cause of a click producing zero visible feedback.

WHAT WAS CHANGED
Only online-adapter.js was changed:
- Sign In, Forgot Password, Sign Out, and Sync Now are wired up immediately, no
  matter what happens with the cloud library (bug 1).
- If the cloud library fails to load, the login screen shows a clear message and a
  "Retry connection" button instead of doing nothing.
- Sign In, Forgot Password, and Sign Out now catch ANY failure — network problems,
  a blocked connection, an unreachable project — and show a plain-English message
  in red under the password field, instead of silently doing nothing (bug 2).

Both scenarios were tested in an automated browser and confirmed fixed: the app
now always shows a message when something goes wrong, and normal sign-in still
works exactly as before when the connection is healthy.

WHAT TO CHECK ON YOUR END
Since clicking Sign In previously did "nothing," it's worth double-checking your
Supabase project is actually live and reachable:
1. Log into supabase.com and open your project. If it shows as "Paused" (common on
   the free tier after a period of no activity), click to restore/resume it.
2. Confirm the Project URL and anon/publishable key in online-config.js exactly
   match what's shown in your Supabase project's Settings > API page.
3. Re-open index.html (or your hosted site) and try Sign In again — with this fix,
   if it still can't connect, you will now see the exact reason on screen instead
   of a blank, unresponsive button.
4. For real day-to-day use, host these files on an HTTPS site (Cloudflare Pages,
   Netlify, etc.) as DEPLOYMENT_CHECKLIST.txt describes, rather than opening
   index.html directly from your desktop — some browsers apply extra restrictions
   to files opened this way.

WHAT YOU NEED TO DO
Re-upload/replace every file in this ZIP where your program lives (or re-extract
this ZIP over your desktop copy). Only online-adapter.js changed — your Supabase
URL/keys in online-config.js were left exactly as they were.
