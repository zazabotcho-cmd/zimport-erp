ZIMPORT — FIX LOG (v3)

NEW IN THIS VERSION: Head Office Action error
--------------------------------------------
On the "ALL PROPOSALS — Head Office Review" page, clicking "Update Head Office
Action" showed:
  "Head Office Action could not be updated. normalizeHeadProposalStatus is not defined."

CAUSE: index.html is built from two big internal code blocks. A helper function
called normalizeHeadProposalStatus was written inside the second block only, so
the first block couldn't see it — like two rooms in a house where one room's
light switch isn't wired to the other room's lights. The Worker submissions list
(which the Update button also refreshes after saving) lives in that first block
and calls this helper, so the save crashed partway through with that exact error.

FIX: the helper is now also made available to the first block, the same way
several other shared helpers already were. I reproduced your exact error message
in an automated test against the original file, applied the fix, and reran the
same test — the error is gone and the update completes normally (verified for
both a plain status change and an "Approved for LCBO Submission" action).

While tracking this down, I checked the whole file for this same kind of mistake
(a helper written in one block but used from the other) and found two more spots
with the identical problem, both around automatically syncing/showing the
Financial Profit pages after a Transportation/Shipment status change. I fixed
those the same way so they don't surface as a similar crash later.

Only index.html changed in this update.

CARRIED OVER FROM v2: "stuck after loading" fixes
--------------------------------------------------
1) If the cloud library (loaded from the internet) was slow, blocked, or failed to
   load, Sign In / Forgot Password / Sign Out / Sync Now did nothing. They're now
   wired up regardless, and a failed cloud library load shows a clear message with
   a "Retry connection" button.
2) Sign In, Forgot Password, and Sign Out now catch any connection failure
   (network hiccup, blocked/unreachable project, etc.) and show a plain message
   instead of silently doing nothing.
Only online-adapter.js changed for these two.

WHAT TO CHECK ON YOUR END (still applies if login is ever unresponsive)
1. In supabase.com, confirm your project isn't "Paused" (common on the free tier
   after inactivity) — resume it if so.
2. Confirm the URL/key in online-config.js match Settings > API in your project.
3. Prefer hosting these files on an HTTPS site (Cloudflare Pages, Netlify, etc.)
   over opening index.html directly from your desktop for day-to-day use.
